### Aqui vou escrever algumas ideias e pensamentos que tive no meio do caminho
- Task para varrer reservas pendentes para liberar caso o tempo maximo de reserva tenha sido atingio
- A plataforma pode ter a tela principal, que abre por padrao ao fazer login ou clicar no icone da plataforma. Uma tela para editar o perfil se for cliente, bem como para ver os ingressos comprados, que devem ser listados por evento
- O usuario deve conseguir selecionar varios tipos de ingresso caso seja show, por exemplo: pista, arquibancada, etc
- Um ponto interessante e que já lidei algumas vezes é o famoso Contains, no meu servico usar um contains em tabelas como historico, celulas, CargaVolumes pode ser catastrófico. Então para a tela principal, tendo em vista a aplicação dos filtros, na busca por soluções cabiveis no caso desse tipo de aplicação, vi que existe uma coisa chamada full-text-search, que basicamente tokeniza as palavras dos eventos e cria dados como [chave:"palavra", paginas=[1, 4, 67]], para que se conheça de antemão em quais paginas do banco tenham a palavra filtrada. Exitem ferramentas excelentes para esse tipo de coisa, mas vi que o postgres tem suporte a esse tipo de conceito com a extensão PostgreSQL Trigram, que quebra a palavra em blocos variados, que combinados com indices, podem achar uma palavra muito rapidamente mesmo que tenham algun erros de digitação. 
- Outro detalhe que encontrei em algumas pesquisas sobre o próprio ticketmaster, é que a arquitetura do mesmo é bem mais bonita do que eu havia pensado. Para garantir a consistencia, basicamente, usa-se um servico de cache para reservas no redis, caso a compra não seja efetivada, esse registro será excluído dessa cache, e como o servico que retorna o mapa de assentos por exemplo, compara esses dados em memória com os do banco de dados, essas aplicação consegue manter esse controle... Como a aplicação é para uma base de usuários menor(dado o escopo do projeto), creio que uma solução usando um tipo de Task/Scheduler que roda de tempos em tempos varrendo assentos reservados com o tempo de reserva ja atingido e oss libera, seja suficiente.
